# 行政复议智能助手 使用说明

本手册面向最终用户,介绍如何启动和使用「行政复议智能助手」(以下简称"本系统")。本系统完全在本地运行,案件材料不出本机。

---

## 一、启动系统

### 1. 前置条件

- 已按模型仓库 `docs/MODEL_ACCESS.md` 完成模型申请、下载,并已启动推理后端(vLLM,8000 端口)与 R79 API(8088 端口)。可用以下命令确认后端就绪:

  ```bash
  curl http://127.0.0.1:8088/health
  ```

- 已安装 harness 依赖(`pip install -r requirements.txt`)。

### 2. 真实模式(日常办案使用)

```bash
cd harness
./run.sh
```

启动后用浏览器打开 `http://127.0.0.1:8090`。Windows 用户运行 `run.ps1`。

### 3. 演示模式(无 GPU 体验/培训使用)

```bash
cd harness
HARNESS_MOCK=1 ./run.sh
```

演示模式不连接真实模型,由内置模拟器返回结构完全一致的合成数据,适合功能演示与操作培训。详见下文"六、演示模式说明"。

---

## 二、界面导览

打开页面后,顶部为页头:左侧是产品名「行政复议智能助手」,右侧是**后端状态徽标**,每 30 秒自动刷新一次:

- **绿色 · 已连接模型服务**:后端正常,可提交真实推理;
- **黄色 · 演示模式**:当前由内置模拟器应答,输出仅用于演示;
- **红色 · 未连接**:连不上 8088 端口的推理服务,请按"常见问题"排查。

页头下方是三个标签页:**案件咨询 / 证据链梳理 / 文书起草**。三个标签页共用同一个"案件材料编辑器"(见下节),在任何一页录入的材料,切换到其他页时仍然保留。

### 标签页一:案件咨询

**输入什么**:在材料编辑器中录入本案材料;在问题输入框中用大白话写下您的问题,例如"该行政处罚决定是否合法?复议申请期限从何时起算?"。可选勾选"**同时检索类案(只读,不注入推理)**",系统会在推理之外单独检索一份最相关的类案原文供参考。

**看到什么**:点击提交后显示加载动画与已用秒数(推理可能需要数分钟,属正常现象)。结果区依次展示:

- **结论卡**:模型给出的总体结论;
- **分析**:分段展开的逐层分析;
- **主张列表**:每条主张带证据状态色块(绿=已证实、蓝=当事人主张、红=存在矛盾、灰=未知)和来源角标(如 `M001:P0003`,表示第 1 份材料第 3 行),可回查原文;
- **局限**:模型明确列出的本案分析局限;
- **类案卡**(若勾选了类案检索):最相关的一份完整类案原文;
- **审计信息**:本次工作流编号、后端生成请求数、路由去向,便于留痕核查。

### 标签页二:证据链梳理

**输入什么**:只需在材料编辑器中录入材料;问题可选,留空时系统使用内置的梳理指令。

**看到什么**:点击提交后展示:

- **统计色块行**:主体、事件、证据、未知事项、矛盾、未知状态的数量概览;
- **事件时间轴**:竖向时间轴,事件按日期排序(日期精确的先排,其次部分精确,日期未知的排最后),按证据状态着色、按日期精度区分实色/半透/虚线框;
- **证据 × 事件支持矩阵**:行是事件、列是证据,单元格标示该证据是否支持该事件;
- **主体表**:本案全部主体及其角色、证据状态;
- **程序步骤与期限**:行政行为的作出步骤与相关期限;
- **矛盾与未知列表**:证据之间的矛盾、尚无法确认的事项;
- 「**导出梳理报告(.md)**」按钮:把以上梳理结果下载为 Markdown 文件存档。

### 标签页三:文书起草

**输入什么**:在材料编辑器中录入材料;在可选信息表单中按需填写申请人、复议机关、复议请求、第三人(均可留空,系统会从材料中推导或标注待补充)。

**看到什么**:点击生成后展示:

- **文书预览**:《行政复议申请书》全文,按"标题 → 申请人 → 被申请人 → 第三人 → 复议请求 → 事实和理由 → 证据目录 → 此致复议机关 → 签名日期"结构成文;缺失信息以【待补充:××】标出;
- **审核提示列表**:列出全部【待补充】项与模型提示的局限,提醒逐项核对;
- 三个按钮:「**下载 .docx**」(按公文样式排版:标题二号方正小标宋/黑体居中,正文三号仿宋、首行缩进 2 字符、1.5 倍行距)、「**下载 .md**」、「**复制全文**」。

> 文书正文由"模型结构化分析 + 确定性模板"组装,模板部分不经过模型自由发挥,保证格式稳定可控。

## 三、材料编辑与文件导入

三个标签页共用"案件材料编辑器":

- 每份材料是一张卡片,含**标题**与**正文**,卡片右上角可**删除**;
- 「**添加材料**」:新增一张空白卡片,手工录入或粘贴;
- 「**从文件导入**」:选择本机 `.txt` / `.md` 文件,一键读入为材料卡片;
- 「**载入示例案件**」:一键载入内置的虚构示例案件(见下节),便于熟悉操作。

材料请尽量粘贴**完整原文,不要先行摘要**——模型会对材料逐行编号(`M001` = 第 1 份材料,`P0001` = 该材料第 1 行),输出中的来源引用都靠这些编号回查。

## 四、示例案件

内置示例案件为**完全虚构的合成案例**:张某不服某县公安局交通管理大队测速处罚(公交决字〔2026〕第0315号),认为测速设备未见检定合格证书、处罚决定书由单位门卫代收,申请行政复议。示例含 4 份材料:行政处罚决定书、送达情况说明、张某陈述申辩书、测速记录打印件,以及预设问题与文书表单信息。适合首次使用时快速体验三大功能。

## 五、演示模式说明

- 开启方式:启动前设置环境变量 `HARNESS_MOCK=1`,即 `HARNESS_MOCK=1 ./run.sh`;
- 演示模式下页头徽标为黄色"演示模式",所有推理结果由内置模拟器生成,**未调用真实模型**,响应中带 `mock_notice` 提示;
- 演示模式的响应结构与真实接口完全一致,三大功能、docx 下载均可完整走通,适合无 GPU 环境下的演示、培训与界面联调;
- 如需在真实模式下联调但又没有 GPU,可另开终端运行 `python -m app.mock_r79`,它会在 8088 端口起一个模拟 R79 API。

## 六、常见问题

**Q1:页面徽标红色,提示连不上 8088 怎么办?**
按顺序排查:① 确认已按 `docs/MODEL_ACCESS.md` 部署模型,且主仓 `scripts/start_backend.sh`(vLLM)与 `scripts/start_api.sh`(R79 API)两个服务都在运行;② 在终端执行 `curl http://127.0.0.1:8088/health`,能返回 JSON 说明后端正常;③ 若 R79 API 改过错口或地址,启动 harness 前设置 `R79_API_BASE` 指向实际地址;④ 只是想体验界面,可改用演示模式 `HARNESS_MOCK=1 ./run.sh`。

**Q2:下载的 docx 打不开?**
① 文书下载令牌在内存中保存、1 小时过期,过期后请回到文书页重新生成再下载;② 请用 Microsoft Word 2016 及以上或 WPS 文字打开;③ 若浏览器拦截了下载,请在地址栏右侧允许本页面下载文件。

**Q3:推理要多久?**
单次工作流包含 3 个逻辑调用、6 次生成请求,每次生成前还要做上下文预算检查,在 GPU 上整体可达分钟级。页面会显示加载动画与已用秒数,请耐心等待,不要重复点击提交;转发超时默认为 660 秒。材料特别长时,如超出上下文预算,系统会在生成前明确拒绝并提示,而不会悄悄截断原文——此时请精简或分批提交材料。

**Q4:类案检索的结果会参与推理吗?**
不会。类案 Wiki 是独立检索端点,只返回最相关的一份完整原文,只读展示,不会自动进入模型上下文。

**Q5:我的案件材料会被上传吗?**
不会。本系统从浏览器到模型全程只走本机回环地址(127.0.0.1),页面不加载任何外部资源,材料不出本机。
